## 定义

**Constraints and Negatives（约束与负向指令）** 指通过明确告诉模型"做什么"（约束）和"不要做什么"（负向）来精确控制输出。负向指令在某些场景下甚至比正向指令更有效。

## 核心理念

> 有时候最好的提示不是说"做这个"，而是说"不要做那个"。约束越多，输出越准。

## 常见约束类型

### 1. 长度约束

```
- 总结成精确的 3 个要点
- 回复不超过 300 字
- 5 个要点以内
```

### 2. 语气约束

```
- 不要使用俚语或幽默
- 不要使用 emoji
- 不要说"谢谢理解"或"请见谅"
```

### 3. 格式约束

```
- 不要使用要点列表，只用一段话
- 不要包含代码，只描述方法
- 不要推荐付费工具
```

### 4. 开头/结尾约束

```
- 不要以"欢迎"或通用问候开头
- 直接以用户在本节会做的事开头
```

## 实例对比

### 没有约束

```
帮我写一封短小的出差期间自动回复邮件。
```

可能输出：包含套话"感谢您的耐心、有限的访问权限、回来后尽快回复"等。

### 带约束

```
帮我写一封短小的自动回复邮件：
- 以我离开的精确日期开头
- 一句话告诉他们急事联系谁
- 不要使用"访问权限有限"、"我会尽快回复"、"感谢您的耐心"
- 简洁但说清楚我何时回来
我从 3 月 1 日到 3 月 25 日不在。
```

输出会精准、无套话。

## 为什么有效

1. **训练数据反映模型的偏好**：模型倾向于输出训练数据中常见的"客套话"，必须显式禁止
2. **缩小输出空间**：约束减少了模型可选的"方向"，输出更聚焦
3. **避免幻觉**：禁止"推荐付费工具"可以避免模型编造产品
4. **研究证明有效**：研究者在提示中常包含大量"不要做的事"列表

## 经典反例

```
❌ 写一段简短的入职文档介绍。
```

```
✅ 写一段简短的入职文档介绍。
   - 以"在本节你将做什么"开头
   - 不要以"欢迎"或通用问候开头
```

## 注意事项

- 不要矛盾：约束相互冲突会让模型陷入混乱
- 不要太多：约束过多会让提示臃肿，影响理解
- 避免双重否定：表达清晰
