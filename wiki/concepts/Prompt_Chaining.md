## 定义

**Prompt Chaining（提示链）** 是一种处理复杂任务的提示工程模式：**把任务拆分为多个步骤，每一步是一个独立的提示，前一步的输出作为后一步的输入**。

## 核心理念

> 与其用一个复杂提示让模型一次性完成所有事情，不如拆成多步，每步验证后再进入下一步。

## 典型流程

```
任务：写一篇技术博客
│
Step 1（提示 1）：给定主题，生成 5 段大纲（JSON 格式）
       ↓
Step 2（提示 2）：基于这个大纲，扩展为 400 字的正文
       ↓
Step 3（提示 3）：把正文转化为 SEO 友好的 meta title 和 description
       ↓
完成
```

## 为什么有效

1. **降低单次复杂度**：每步只关注一件事，模型更专注
2. **可验证可调整**：每步输出可以检查，错误及时修正
3. **可重用**：每个步骤可以独立改进或替换
4. **避免遗漏**：复杂提示中模型可能忽略某些细节
5. **更易调试**：找到问题在哪一步更容易

## 实践示例

### 不推荐（单次复杂提示）

```
帮我写一篇关于"远程工作"的技术博客：
- 生成 5 段大纲
- 写完整正文
- 加 SEO meta
- 翻译成英文
- 配 3 张图的建议
```

模型可能：跳过某个步骤、各部分质量不均、难以局部修改。

### 推荐（提示链）

```
[Prompt 1] 给定主题"远程工作"，生成 5 段大纲（JSON）

[等待结果，验证大纲质量]

[Prompt 2] 基于这个大纲，每段扩展为 200-300 字正文
{粘贴上一步的输出}

[等待结果，验证内容]

[Prompt 3] 为这篇博客生成 SEO 友好的 meta title 和 description
{粘贴上一步的输出}
```

## 在 Agent 系统中的应用

[[Claude_Code]]、[[Gemini_CLI]] 等智能体内部大量使用提示链：
- 任务分解（识别子任务）
- 逐步执行（每步独立提示）
- 状态维护（前一步输出 → 下一步输入）

## 与其他技术的关系

| 方法 | 触发方 | 适用场景 |
|------|--------|----------|
| Prompt Chaining | 用户/系统预定义 | 任务可拆分为线性步骤 |
| [[Iterative_Refinement|迭代精化]] | 用户驱动 | 任务模糊，需逐步逼近 |
| [[Interview_Style_Prompting|访谈式提示]] | 模型驱动 | 缺乏初始上下文 |
| [[ReAct]] | 模型驱动 | 需要工具调用 |

## 配合 [[Structured_Output|结构化输出]] 使用

提示链中各步骤的输出通常是 JSON/YAML 等结构化格式，便于程序化传递到下一步。
